# 本地量化股票分析智能体项目宪法

## 核心原则

### I. 本地数据是唯一量化事实来源

所有行情、板块、特征、预测、实际结果、报告和模型版本 MUST 在本地持久化后，
才可作为计算、展示或解释的量化事实。每条记录或可定位的数据批次 MUST 同时包含
来源、市场时间、采集时间和数据版本；任何缺少这些元数据的数字 MUST 被拒绝进入
预测、回测、报告和大模型上下文。验收 MUST 能从任一展示数字反查本地记录及其版本。

理由：本地、版本化且带时点的数据链是离线复现、审计和跨工具一致性的基础。

### II. 严禁未来数据泄漏

训练、验证和回测数据 MUST 按市场时间顺序切分，MUST NOT 随机打乱导致未来样本进入
过去窗口。任一特征 MUST 仅使用预测时点已经可获得的数据，并记录其数据截止时点。
特征生成、标签生成、板块成分、复权、交易日历和跨市场换算 MUST 接受时点一致性测试。
发现或无法排除未来数据泄漏时，相关模型、回测和报告 MUST 立即判定无效并停止发布。

理由：未来信息污染会让评估结果失真，且无法通过增加样本或模型复杂度补救。

### III. 大模型仅编排与解释

大模型 MUST 仅用于意图理解、工具编排和基于工具结果的解释。大模型 MUST NOT 凭空
生成、补齐或改写行情、特征、预测、回测或收益数字。所有量化数字 MUST 能追溯到
一次具有工具名、参数、调用时间、结果版本和结果标识的 MCP（模型上下文协议）工具
结果；缺少溯源证据时 MUST 明确拒绝给出数字，不得用估算值代替。

理由：把计算限定在结构化工具内，才能使自然语言解释保持可审计和可复现。

### IV. 概率化预测与风险披露

每次预测 MUST 指定预测周期，并表达为上涨、震荡、下跌三个互斥结果的概率；概率之和
MUST 满足契约规定的数值容差。预测 MUST 同时包含置信度、主要依据、数据新鲜度、模型
版本和风险因素。预测界面和报告 MUST 持续显示“研究参考，不构成投资建议”。任何输出
MUST NOT 承诺收益、保证方向或暗示无风险结果。

理由：概率和风险信息比确定性结论更符合模型能力边界，也便于后续校准和复盘。

### V. 候选模型受控晋级

自学习流程 MUST 只能生成候选模型，MUST NOT 直接替换正式模型。候选模型发布前 MUST
依次通过时间序列回测、与预先登记的简单基准比较、影子运行和人工批准；每一关 MUST
保存输入版本、指标、结论、审批人和时间。任一门禁失败或证据缺失时发布 MUST 停止。
正式发布 MUST 保留上一可用版本、原子切换机制和经过验证的回滚路径。

理由：模型改进必须由独立证据确认，并能在退化或事故发生时恢复。

### VI. 原始数据与预测快照不可变

原始行情和预测快照 MUST 追加保存，MUST NOT 静默覆盖、原地改写或删除历史值。任何
修订 MUST 写成带来源、修订原因、创建时间和前序版本引用的新版本。读取接口 MUST 能
区分原始版本、修订版本和当前推荐版本，审计流程 MUST 能重建完整版本链。

理由：不可变快照是预测复盘、问题定位和防止事后修改历史的必要条件。

### VII. 后台计算与桌面界面隔离

行情更新、回测和训练 MUST 与 PySide6 界面线程和界面生命周期隔离，并通过结构化任务
状态通信。后台失败、超时、取消或进程崩溃 MUST NOT 阻塞或破坏桌面应用，MUST NOT
污染已经验证的数据。写入 MUST 使用临时结果、完整性校验和成功后提交机制；失败结果
MUST 保持隔离并记录可诊断错误。

理由：耗时和高风险计算不能降低桌面应用可用性或破坏可信数据。

### VIII. 第一阶段仅限研究与模拟

第一阶段 MUST 只提供研究、模拟预测和历史验证。产品、Skill、MCP 工具和内部服务
MUST NOT 连接券商账户，MUST NOT 接收或保存券商交易凭据，MUST NOT 创建、提交、
修改或撤销真实订单。任何需要真实交易能力的规格 MUST 先通过宪法修订，当前版本下
必须停止。

理由：研究系统与真实交易系统具有不同的合规、资金和操作风险边界。

### IX. 结构化契约与工程质量

每个 Skill、MCP 工具和内部服务 MUST 定义版本化的结构化输入、输出与错误契约，实施
最小权限、参数校验、超时和错误处理，并产生不泄露凭据的结构化日志。契约、权限边界、
错误路径和关键业务规则 MUST 有自动化测试。未通过契约测试或安全检查的接口 MUST NOT
被界面、大模型或发布流程调用。

理由：明确边界和自动验证能够阻止绕过数据、权限及模型发布规则的隐式通道。

### X. 跨平台同等验收

Windows、macOS 和 Linux MUST 作为正式目标平台。路径、目录、进程、文件锁、通知、
字体、高 DPI、权限和打包等平台差异 MUST 集中封装，MUST NOT 散落在业务逻辑中。
每个正式版本 MUST 在三类平台分别完成安装、启动、核心流程、升级和本地数据恢复验收；
任一平台未通过时 MUST 明确阻止将该版本标记为全平台可发布。

理由：跨平台支持是产品承诺，必须由真实平台证据而非代码可编译性证明。

### XI. 简体中文项目表达

项目自行编写的设计、需求、计划、任务、测试、使用和维护文档，以及代码注释、文档
字符串和示例说明 MUST 使用简体中文。代码标识符、命令、文件名、协议字段、数据表
字段、第三方 API 名称和专有技术名词 MAY 保留英文；英文缩写或专有名词首次出现时
MUST 在不影响可读性的前提下提供中文说明。第三方原文 MUST 紧邻提供中文解释。注释
MUST 解释业务规则、数据时点、跨市场差异、风险边界或非显然理由，MUST NOT 机械重复
代码表面含义。无法安全本地化的外部生成文件 MUST 保持原样并在中文文档中说明用途。

理由：统一语言降低维护成本，而保留必要技术标识可维持接口兼容性和准确性。

## 强制约束

- 所有预测界面、导出内容和报告 MUST 显示原文“研究参考，不构成投资建议”，不得使用
  弱化风险含义的替代措辞。
- 量化数据契约 MUST 明确来源、市场时间、采集时间、数据版本和新鲜度的字段、格式、
  时区与缺失处理；缺失或过期数据的降级行为 MUST 可测试且不得伪装为实时数据。
- 预测契约 MUST 明确预测周期、三分类标签、概率容差、置信度、依据、风险因素、模型
  版本和 MCP 结果引用；界面与报告 MUST 使用同一契约，不得各自推导数字。
- 数据修订、模型晋级、人工批准、发布和回滚 MUST 形成追加式审计事件。
- 第一阶段的任何依赖、权限或接口若具备真实交易能力，即使界面未暴露，也 MUST 视为
  违反研究边界。

## 开发工作流与质量门禁

1. **规格门禁**：每份规格 MUST 明确适用的数据时点、量化数字来源、预测表达、研究
   边界、失败行为、平台范围和免责声明。与本宪法冲突或无法验证的规格 MUST 停止。
2. **计划门禁**：计划 MUST 在研究前和设计后各执行一次宪法检查，并为每条适用原则
   指向具体设计、契约、测试或发布证据。原则不得以“后续处理”规避。
3. **任务门禁**：任务 MUST 把每项适用的 MUST 映射到带准确文件路径的实现任务和先行
   验证任务；数据时点、MCP 溯源、不可变快照、模型晋级、隔离失败和跨平台验收不得
   仅作为最终人工检查。
4. **实现与评审门禁**：实现 MUST 先证明契约及失败路径可测试，再接入界面或大模型。
   评审 MUST 检查数据版本链、时间切分证据、数字溯源、权限范围、日志脱敏和中文规范。
5. **发布门禁**：发布证据 MUST 包含自动化测试结果、三平台验收状态、数据与模型回滚
   演练结果，以及所有预测界面和报告的免责声明检查。任一强制证据缺失 MUST 停止发布。

## 治理

- 本宪法高于所有规格、计划、任务、实现约定和交付期限。任何产物与宪法冲突时，
  相关工作 MUST 立即停止；只能修正产物或按本节正式修订宪法，MUST NOT 通过例外、口头批准或
  风险接受绕过原则。
- 修订宪法 MUST 记录修订原因、语义化版本变化理由、受影响原则、受影响产物、迁移或
  补救要求、批准人和批准日期，并同步检查 Spec Kit 模板及运行时指导文档。
- 版本 MUST 遵循语义化版本：删除原则、弱化不可绕过规则或改变治理兼容性为 MAJOR；
  新增原则或实质扩大强制范围为 MINOR；不改变含义的澄清为 PATCH。首次正式批准为
  1.0.0。
- 每次规格、计划和任务评审 MUST 逐条记录宪法合规结论及证据位置。发现违反项时 MUST
  标为阻塞，修复并重新评审后方可继续。
- 宪法合规性 MUST 由自动化检查和人工评审共同验证；自动化通过不得替代涉及投资风险、
  模型批准或范围边界的人工判断。

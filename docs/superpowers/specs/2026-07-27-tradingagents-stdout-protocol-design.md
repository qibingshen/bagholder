# TradingAgents 标准输出协议修复设计

## 目标

修复 TradingAgents 研究子进程在模型或工具依赖输出额外标准输出时，主程序将其判定为协议错误的问题；恢复研究管道对长鑫科技（CN:688825.SH）的可用性，并保持真实交易关闭。

## 范围与约束

- 子进程对主程序的标准输出仍只能包含一行 UTF-8 JSON 响应。
- 第三方库的诊断输出不得污染该响应；应转入标准错误。
- 客户端继续拒绝额外标准输出，不能通过“取最后一行 JSON”弱化协议。
- 修复后仅重试 PAPER 模式，使用既有 `paper-main` 本地模拟账户；不得开启任何 LIVE 配置。

## 设计

在 `integrations/tradingagents/runner.py` 的请求分发期间，保存原始标准输出描述符，并将进程级文件描述符 1 导向标准错误。运行器通过保存的原始描述符直接写出唯一 JSON 响应，不在进程退出前恢复文件描述符 1；这样依赖的缓冲或延迟输出也只能进入标准错误。

`TradingAgentsClient` 保持现有的单行 JSON 校验：若运行器以外的异常仍产生额外输出，客户端继续抛出 `TradingAgentsProtocolError`，研究和模拟盘管道必须停止。

## 错误处理

- 依赖或模型异常：运行器只输出 `{\"ok\":false,...}` 的单行 JSON；细节仅写标准错误。
- 标准输出隔离失败：以稳定错误码结束，不能输出部分研究结果或创建订单。
- 新股数据不足、风险门禁拒绝或研究决策为非买入：允许记录结果，但不创建模拟订单。

## 验证

1. 添加回归测试：模拟依赖直接写入标准输出，断言运行器标准输出仍为唯一 JSON，诊断文本在标准错误。
2. 运行 TradingAgents 客户端和运行器单元测试，确认原有“额外标准输出必须拒绝”测试仍通过。
3. 使用 CN:688825.SH 重跑 PAPER 研究管道，记录运行状态；只有管道生成提案且 PAPER 审批通过时才允许生成模拟订单。

# 本地量化股票分析智能体设计

**状态**：已确认

**确认日期**：2026-07-10

**目标平台**：Windows、macOS、Linux

## 1. 产品目标

构建一个 Python 桌面应用，为个人研究者提供 A 股、港股和美股的行情、板块、
量化分析、概率预测、历史验证和大模型对话能力。系统以本地数据为事实来源，
通过 Skill 编排分析流程，通过 MCP 向大模型提供结构化工具。

系统输出的是带时间范围、概率、置信度、依据和风险因素的研究结果，不承诺收益，
不在首期连接券商或执行真实交易。

## 2. 已确认范围

- 支持 A 股、港股和美股，以及各市场主要指数。
- 支持行业、概念、地域等主要板块和用户自定义板块。
- 提供实时或准实时行情、历史行情、K 线、技术指标和板块轮动分析。
- 预测未来 1 日、5 日和 20 日上涨、震荡、下跌的概率。
- 提供每日市场报告、个股诊断、历史预测复盘和模型回测。
- 提供可与大模型对话的 Stock Analysis Skill 和标准 MCP Server。
- 行情、特征、预测、实际结果、报告和模型版本均量化存储在本地。
- 候选模型可以定期学习，但正式模型的发布必须经过回测、影子运行和人工批准。
- 桌面端采用 PySide6，并分别构建 Windows、macOS 和 Linux 安装包。

## 3. 明确不在首期范围

- 券商账户登录、真实下单和自动交易。
- 对收益或涨跌方向作确定性承诺。
- 绕过授权抓取受限行情，或把延迟行情标记为实时行情。
- 让大模型直接生成行情数字、修改原始行情或自行发布生产模型。
- 为所有 Linux 发行版提供同等安装支持；首期正式验证 Ubuntu 22.04 和 24.04。

## 4. 架构方案

采用已确认的模块化本地架构：

```text
PySide6 Desktop
    ├── 市场与板块看板
    ├── 自选股和自定义板块
    ├── 个股分析与预测
    ├── AI 对话与每日报告
    └── 回测、模型、任务和设置
             │
       Local Application API
        ├── Market Data Adapters
        ├── Quant Feature Engine
        ├── Prediction Engine
        ├── Backtest Engine
        ├── Learning Pipeline
        ├── Report Service
        └── Scheduler
             │
    DuckDB + Parquet + SQLite + Model Registry
             │
          MCP Server
```

界面进程只负责展示和交互。行情更新、回测和训练进入后台任务队列；模型训练使用
独立进程。MCP Server 与桌面端共享应用服务，不绕过数据和权限边界。

## 5. 组件边界

### 5.1 PySide6 桌面端

提供市场总览、板块行情、个股分析、自选股、自定义板块、AI 对话、预测中心、
回测中心、每日报告、模型管理、数据任务和系统设置页面。耗时任务必须可查看进度、
取消、重试，并且不能阻塞界面。

### 5.2 行情适配器

为每个获授权数据源提供统一接口，输出标准化证券代码、市场、时间、币种、价格、
成交量、复权信息和数据新鲜度。数据源选择在技术研究阶段根据授权、覆盖范围、
延迟、稳定性和成本形成决策记录；核心服务不绑定单一供应商。

### 5.3 量化与预测引擎

量化引擎生成个股、板块、大盘环境和跨市场关联特征。预测引擎至少包含简单基准、
可解释机器学习模型和融合层。任何高级模型都必须与简单基准比较，且不得使用预测
时点之后的数据。

### 5.4 回测与学习流水线

回测使用按时间滚动或扩展窗口，计入手续费、滑点、停牌和不可成交约束。学习流水线
只能生成候选模型，不能直接覆盖正式模型。

### 5.5 Skill 与 MCP

Stock Analysis Skill 负责编排每日分析、个股诊断、板块轮动、历史回测、预测复盘和
候选模型评估。MCP 提供结构化、可审计、默认只读的工具，例如：

- 查询市场状态、行情、K 线和板块成员；
- 计算技术指标、相对强弱和板块热度；
- 请求预测、解释预测和查询历史预测；
- 启动回测并查询结果；
- 生成每日报告；
- 查询数据新鲜度、后台任务和模型版本。

发布、回滚或删除操作必须使用单独权限，并要求桌面端人工确认。大模型不得通过通用
文件或 SQL 工具绕过这些契约。

## 6. 本地数据设计

- **DuckDB**：证券、交易日历、板块、板块成员历史、预测、实际结果、任务、报告和
  模型元数据。
- **Parquet**：原始及标准化分钟线、日线和特征快照等大规模时序数据。
- **SQLite**：桌面设置、窗口状态、用户偏好、对话索引和非量化应用状态。
- **模型注册表**：模型文件、训练参数、代码版本、数据范围、特征版本、评估报告和
  发布状态。

原始行情采用追加式保存。修订数据必须保留来源和版本，不能静默覆盖。每条预测保存
市场时间、生成时间、预测周期、概率、置信度、数据版本、特征版本和模型版本。

自定义板块必须保存成员关系的生效区间，历史回测只能使用当时有效的成分。三大市场
分别维护交易日历、交易时段、时区、代码规则和币种；跨市场比较明确汇率基准和换算
时间。

## 7. 数据与学习闭环

```text
授权行情源 → 原始快照 → 清洗标准化 → 特征快照 → 预测快照
    → 到期结果回填 → 时间序列评估 → 候选模型训练
    → 基准比较 → 影子运行 → 人工批准 → 发布或拒绝
```

预测快照产生后不可回写修改。修正只能形成新版本并保留原记录。候选模型只有在预先
定义的评估指标上满足门槛、没有数据泄漏、通过影子运行且获得人工批准后才能发布。
正式模型和数据结构升级都必须支持回滚。

## 8. 桌面信息架构

- **市场总览**：三大市场状态、主要指数、涨跌分布和成交活跃度。
- **板块行情**：主要板块、自定义板块、强弱排名、板块轮动和跨市场比较。
- **个股分析**：K 线、成交量、技术指标、所属板块、相对强弱和预测解释。
- **自选与分组**：股票分组、自定义板块、批量导入导出和成员历史。
- **AI 对话**：基于 MCP 工具回答行情、板块、预测、回测和报告问题。
- **预测中心**：1 日、5 日、20 日三分类概率、置信度和风险因素。
- **回测中心**：基准比较、命中率、收益曲线、回撤和概率校准。
- **报告中心**：每日总结、强弱板块、关注个股和历史预测复盘。
- **模型管理**：当前与候选模型、训练记录、批准、拒绝和回滚。
- **数据与任务**：数据源新鲜度、更新任务、训练任务、失败重试和日志。
- **系统设置**：数据源、大模型、MCP、存储、代理和跨平台选项。

## 9. 异常与安全边界

- 数据源不可用时展示最近有效数据及其时间，明确标记过期，并暂停依赖实时数据的
  预测。
- 多数据源冲突保留差异记录，按配置的优先级决策，禁止静默拼接。
- 市场休市、停牌、退市、涨跌停、拆股分红和缺失数据分别处理。
- 后台任务支持超时、重试、取消和断点恢复；失败不能阻止桌面端启动。
- 数据库迁移前备份；迁移或模型发布失败时自动保留原版本。
- 大模型不可用时，行情、图表、量化分析和本地报告仍然可用。
- 所有预测界面和报告持续显示“研究参考，不构成投资建议”。

## 10. 跨平台交付

业务代码共用一套代码库，但安装包必须在目标平台分别构建和验证。平台适配层处理
路径、系统托盘、通知、字体、高 DPI、深色模式、权限和自动启动。

- Windows：正式支持 Windows 10/11。
- macOS：分别验证 Apple Silicon 和 Intel 架构。
- Linux：首期正式支持 Ubuntu 22.04/24.04，其他发行版为尽力支持。

## 11. 中文文档与注释规范

- 项目自行编写的设计、需求、计划、任务、测试、使用和维护文档必须使用简体中文。
- 项目自行编写或修改的代码注释、文档字符串和示例说明必须使用简体中文。
- 代码标识符、命令、文件名、协议字段、数据表字段、第三方 API 名称和专有技术名词
  可以保留英文，以保证兼容性和准确性。
- 英文缩写或专有名词首次出现在中文文档中时，应尽量补充中文说明。
- 第三方原文可以保留原语言，但必须提供紧邻的中文解释。
- 注释应解释业务规则、数据时点、跨市场差异、风险边界或非显然设计理由，禁止添加
  只重复代码表面含义的无价值注释。
- 无法安全本地化的外部工具生成文件保持原样，并在项目中文文档中说明其用途。

## 12. 测试与验收

- 对证券代码、时区、交易日历、复权、币种和板块成员历史进行数据契约测试。
- 对特征生成执行时点一致性测试和未来数据泄漏测试。
- 对预测概率执行校准、稳定性和基准比较测试。
- 对回测执行手续费、滑点、停牌和不可成交场景测试。
- 对 MCP 工具执行结构化输入输出、权限、超时和错误契约测试。
- 对 PySide6 页面执行关键流程、后台任务和崩溃恢复测试。
- 在 Windows、macOS、Linux 分别执行安装、启动、升级和本地数据恢复测试。
- 使用固定样例验证 AI 回答中的所有行情数字均能追溯到 MCP 工具结果。
- 检查项目自编写的文档、代码注释和文档字符串是否符合简体中文规范。

## 13. 分阶段交付

首个可验收闭环为：历史行情采集、本地存储、特征计算、简单基准预测、时间序列
回测、MCP 查询、AI 解释和每日报告。随后再增加实时行情、完整板块、跨市场比较、
高级模型和候选模型学习流水线。

任何预测模型进入正式状态前，至少完成一个覆盖 30 个交易日的影子运行周期。首期
完成标准不包含实盘交易能力。

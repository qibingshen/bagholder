# 多数据源行情接入设计

## 目标

在不改变本地事实、时点一致性与不自动交易边界的前提下，为行情系统建立可插拔数据源能力。
首个适配器为新浪 A 股 HTTP 行情接口；后续接入 Finnhub 美股和其他合法数据源时，不修改核心
市场服务、存储版本链或桌面页面。

## 方案选择

采用“适配器注册表 + 每源独立契约”方案。

- 每个适配器声明支持市场、数据类别、授权方式、限频、字段映射和新鲜度能力。
- 核心服务只接收规范化行情与完整溯源；不依赖供应商 SDK 或供应商字段。
- 同一证券来自不同数据源的结果保留各自来源和版本，不拼接或静默覆盖。
- 数据源缺失、授权失效、限频、字段不完整或市场时间不可验证时，返回结构化降级状态。

未采用“页面直接请求供应商接口”，因为它会绕过权限、版本、审计和测试边界；未采用“单一供应商
硬编码”，因为无法安全扩展美股、港股或用户后续自带的合法数据源。

## 新浪 A 股适配器

- 端点固定为 `http://hq.sinajs.cn/list={代码列表}`，仅允许 HTTP `GET`，不发送凭据。
- 代码必须在适配器内规范化为新浪 A 股前缀格式，例如 `sh600000`、`sz000001`；无效或跨市场代码
  直接拒绝，不尝试猜测。
- 响应会先保存为原始工件，再解析为规范化报价。每条报价必须包含新浪来源标识、市场时间、采集 UTC
  时间、数据版本和新鲜度。
- 若响应没有可验证市场时间、市场时间无法解析，或数据年龄超过阈值，则不得标记为实时。A 股只有
  在年龄不超过 5 秒时为 `REALTIME`；6–60 秒为 `NEAR_REALTIME`；超过 60 秒为 `DELAYED`；交易
  时段超过 15 分钟为 `STALE`。休市时为 `CLOSED`。
- 新浪接口未承诺的数据类别不会伪造：若不能提供合规的历史日线、复权或公司行动，相关功能明确降级，
  不用于当前预测。

## Finnhub 与后续数据源

- Finnhub 作为美股候选适配器，使用系统钥匙串保存用户密钥；应用数据库、日志、MCP 响应、备份和报告
  只保存可撤销引用，不保存明文。
- 凭据配置记录数据源、可用市场、授权状态、最近验证时间和限频策略；凭据失效时只允许使用本地历史或
  合法公开数据，并停止不满足新鲜度的当前行情与预测。
- 新供应商以同一适配器契约注册，并针对授权、限频、冲突、字段缺失与新鲜度分别提供测试。未注册或
  不支持的市场默认不可用。

## 冲突、版本与审计

- 不同数据源的同一证券和时点数据以来源独立版本保存；展示层选择值必须说明选择规则和备选来源差异。
- 原始响应、标准化行情和特征输入均追加保存。修订只能创建新版本并保留父版本与修订原因。
- 每次采集、失败、降级、授权状态变化和展示值选择均追加审计事件。任何量化数字均可回溯到适配器
  响应工件和数据版本。

## 验收与实施顺序

1. 先写新浪代码规范化、响应解析、缺失字段、无市场时间、过期、限频和来源溯源的失败测试。
2. 实现适配器协议、适配器注册表和新浪只读适配器。
3. 将原始响应与标准化日线/报价接入版本化暂存提交；验证后才可展示。
4. 实现新鲜度和降级状态，再接入桌面市场页面。
5. 新增 Finnhub 时复用协议与安全凭据服务，并补充美股交易时段、时区和限频验收。

## 范围边界

本设计不连接券商、不接收券商凭据、不提交订单、不执行自动交易。新浪公共接口不因接口可访问而被
默认视为实时或可用于预测；所有预测和报告仍必须显示“研究参考，不构成投资建议”。

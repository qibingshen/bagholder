# 生产级真实下单闭环设计

## 1. 背景与目标

当前项目已经具备 TradingAgents-Astock 研究入口、公共 A 股日 K 证据、
PAPER 交易、账户级 vn.py Gateway 路由、实盘双开关、交互确认和幂等提交。
中信证券与国泰海通证券均已注册为独立账户，但当前没有两家券商的官方
程序化交易 SDK、测试环境或受信私有插件，因此账户保持
`API_UNAVAILABLE`。

本设计的目标是在不依赖未知券商 SDK 细节的前提下，先完成可自动验证的
生产安全闭环、完整订单生命周期、启动与断线对账以及通用插件合约。取得
券商授权后，先接入中信测试环境，再用国泰海通验证核心平台不存在券商耦合。

## 2. 范围

### 2.1 本阶段包含

- 修复拒单、审批过期和执行异常的状态处理；
- 增加券商证券级实时行情契约；
- 验证确认通道后刷新行情、资金、持仓，执行二次风控并确认最终限价；
- 建立委托、成交、撤单、状态事件和对账的持久化模型；
- 支持订单查询、撤单、状态更新、未知状态处理和重启恢复；
- 建立账户冻结、重连和对账恢复机制；
- 建立中信和国泰海通共用的私有插件接口及合约测试；
- 定义中信先行、国泰海通复用的测试环境验收矩阵；
- 增加 SQLite schema migration 和部署验收门槛。

### 2.2 本阶段不包含

- Web 或桌面界面；
- 常驻策略调度和自动策略授权；
- 回测系统；
- PAPER 手续费、税费、滑点和成交量模拟精细化；
- 未取得官方资料前猜测中信或国泰海通 SDK 类型及字段；
- 把公共日 K 当作实盘委托价格；
- 在券商测试环境验收完成前开启生产账户。

## 3. 实施原则

- LIVE 失败不得转成 PAPER；
- 一个账户失败不得尝试其他账户；
- 未确认提交结果不得自动重发；
- 公共行情只用于研究，LIVE 价格必须来自提案账户对应的券商 Gateway；
- CLI 在读取券商事实前先验证 `--confirm-live` 和交互终端，读取后再要求
  输入包含最终限价的精确确认文本；
- 提交前风控和最终价格确认必须使用同一次新鲜事实快照；
- 所有状态变化均追加不可变事件，不覆盖历史；
- 所有外部异常转换为脱敏稳定错误码；
- SDK 密钥、账号密码、会话令牌和原始敏感异常不得写入仓库或 SQLite；
- 中信与国泰海通使用同一平台接口和合约测试；
- 总开关和账户开关默认关闭。

## 4. 总体架构

建设分为四个可以独立验收的阶段。

### 4.1 实盘安全正确性

修复 `REJECTED → LIVE_SUBMITTED` 错误，审批过期和执行异常必须落入明确
终态。新增提交前事实刷新和二次风控，任何行情、资金、持仓或账户事实缺失
都拒绝提交。

### 4.2 订单生命周期与恢复

建立统一委托状态机、订单事件、成交明细、撤单、轮询、启动对账、账户冻结
和幂等恢复。查询和风险降低型撤单在账户冻结时仍可使用，新开仓被阻止。

### 4.3 中信插件契约与测试环境接入

公共仓库只定义券商无关的 SPI、合约测试和受信加载机制。取得中信官方
SDK 和测试账户后，在私有插件中实现接口并通过安全及故障恢复验收。

### 4.4 国泰海通复用验证

国泰海通只新增私有插件和配置，不修改核心订单服务。若接入必须增加券商
分支逻辑，则通用抽象验收失败，需先修正平台边界。

## 5. 核心组件

### 5.1 BrokerMarketDataService

按账户和证券查询券商实时快照，至少返回：

- 证券标识；
- 最新价、买一价、卖一价；
- 行情时间和接收时间；
- 停牌及可交易状态；
- 涨停价、跌停价；
- 最小价格变动单位；
- 数据源会话标识。

公共日 K 不得实现该接口，也不得作为 LIVE 限价来源。

### 5.2 PreSubmitRiskService

LIVE 审批必须显式提供 `--limit-price`。平台先验证 `--confirm-live` 和交互
终端，再执行：

1. 查询账户运行状态；
2. 查询证券级实时行情；
3. 查询资金和持仓；
4. 查询活动订单和当日成交；
5. 校验用户限价；
6. 计算可用资金、可卖数量、集中度、换手、盈亏和回撤；
7. 校验交易时间、停牌、涨跌停、价格步长和整手规则；
8. 要求用户输入券商、账户、证券、方向、数量和最终限价；
9. 保存 `PRE_SUBMIT` 风控快照；
10. 生成与最终执行请求和最终限价绑定的二次 `RiskVerdict`。

事实快照超过配置的有效期后不得提交，必须重新刷新和确认。

### 5.3 LiveOrderService

负责提交、查询和撤单，并执行以下回执校验：

- 回执账户必须与请求账户一致；
- 回执证券、方向、数量必须与请求一致；
- 券商订单号不能为空；
- `accepted=false` 或 `status=REJECTED` 只能进入拒单终态；
- 超时或无法确认是否受理时进入 `UNKNOWN`；
- 同一幂等键不得产生第二次券商提交；
- 回执不完整或身份不匹配时熔断账户。

### 5.4 OrderLifecycleService

接受轮询结果或券商回报，验证合法状态转换，更新订单当前快照，并为每次变化
追加不可变 `order_event`。部分成交保存独立成交明细，不能只修改订单已成交
数量。

### 5.5 AccountReconciliationService

在启动、重连、`UNKNOWN` 和人工触发时执行：

- 查询资金；
- 查询持仓；
- 查询活动及当日订单；
- 查询当日成交；
- 与本地未终结订单、成交和账户快照比较；
- 保存对账批次及差异；
- 一致时进入 `READY`；
- 无法解释的差异进入 `HALTED`。

`HALTED` 禁止新开仓，允许查询和对现有活动订单执行风险降低型撤单。

### 5.6 BrokerPluginContractSuite

所有私有插件运行同一套合约测试，覆盖身份、账户隔离、实时行情、资金、
持仓、委托、撤单、订单、成交、拒单、部分成交、超时、断线、重连和幂等。
合约不得为特定券商降低必需能力。

## 6. 真实下单数据流

```text
研究证据
→ 订单提案和参考价格
→ 首次风控
→ LIVE 审批提供券商、账户和用户限价
→ 验证确认开关及交互终端
→ 刷新券商实时行情、账户、资金、持仓、订单和成交
→ 校验用户限价并执行二次风控
→ 精确确认券商、账户、证券、方向、数量和最终限价
→ 保存事实快照及二次风控
→ 账户级 Gateway 提交
→ 回执身份及状态校验
→ 保存订单当前快照和不可变事件
→ 轮询或回报更新
→ 成交、撤单、拒单或未知终态
→ 资金、持仓、订单、成交对账
```

任何环节失败都不得切换券商、转为 PAPER 或自动重复发单。

## 7. 状态机

### 7.1 正常状态

```text
CREATED
→ PRECHECK_PASSED
→ SUBMITTING
→ SUBMITTED
→ PARTIALLY_FILLED
→ FILLED
```

### 7.2 分支终态

```text
REJECTED
CANCELLED
EXPIRED
```

### 7.3 异常状态

```text
UNKNOWN
RECONCILIATION_REQUIRED
```

状态约束：

- `accepted=false` 只能进入 `REJECTED`；
- 提交超时不能推断为失败，进入 `UNKNOWN`；
- `UNKNOWN` 后禁止自动重发并冻结账户新开仓；
- 重复恢复使用原幂等键；
- 非法状态转换拒绝写入并追加安全审计事件；
- `PARTIALLY_FILLED` 撤单后保留已有成交，剩余数量进入撤单流程；
- `FILLED`、`REJECTED`、`CANCELLED` 和 `EXPIRED` 不接受反向状态转换。

## 8. 持久化与迁移

新增版本化迁移和以下逻辑表：

| 表 | 责任 |
|---|---|
| `schema_migrations` | 数据库版本和迁移时间 |
| `live_orders` | 完整实盘委托当前快照 |
| `order_events` | 不可变订单状态事件 |
| `trade_fills` | 成交明细和券商成交号 |
| `cancel_requests` | 撤单请求、回执和状态 |
| `risk_checks` | 首次及提交前二次风控事实 |
| `account_reconciliations` | 对账批次、结果和差异 |
| `account_runtime_states` | 账户 READY、RECONCILING、HALTED 状态 |

每条交易记录必须包含账户、券商、内部订单号、券商订单号、关联 ID、幂等键、
创建时间、更新时间和稳定错误码。敏感凭据和原始 SDK 异常不得入库。

旧 `execution_receipts` 通过迁移保留为历史兼容数据；迁移不得删除或覆盖旧记录。

## 9. 故障处理

| 条件 | 处理 |
|---|---|
| 行情过期或行情查询失败 | 拒绝提交 |
| 资金或持仓查询失败 | 拒绝提交 |
| 人工确认后事实已过期 | 重新刷新并再次确认 |
| 提交前断线 | 保持未提交，可创建新审批尝试 |
| 提交超时 | `UNKNOWN`，冻结新开仓并立即对账 |
| 券商明确拒单 | 保存脱敏拒单原因，进入 `REJECTED` |
| 部分成交后撤单 | 保存已有成交，对剩余数量发起撤单 |
| 回执账户或证券不匹配 | 熔断账户并记录安全事件 |
| 启动发现未终结订单 | 进入 `RECONCILING`，完成前不得 READY |
| 一个账户故障 | 只影响该账户，不影响其他账户 |

## 10. CLI 与操作入口

在现有 CLI 上增加：

```text
broker account show <account_id>
broker quote <account_id> <security_key>
broker funds <account_id>
broker positions <account_id>
broker orders <account_id>
broker trades <account_id>
order cancel <order_id>
order reconcile <order_id>
account reconcile <account_id>
```

所有 LIVE 修改操作继续要求显式账户、券商和交互确认。查询命令输出脱敏 JSON，
不输出插件路径、摘要、密钥、会话令牌或 SDK 原始异常。

## 11. 自动化测试

### 11.1 单元测试

- 回执账户、证券、方向和数量校验；
- 拒单、超时和非法状态转换；
- 二次风控和事实过期；
- 交易时段、涨跌停、价格步长和整手规则；
- 部分成交和剩余可撤数量；
- 账户冻结及解冻条件；
- 数据库迁移的前向兼容和幂等。

### 11.2 集成测试

使用可脚本化 Gateway 覆盖：

- 正常提交和全部成交；
- 明确拒单；
- 部分成交；
- 撤单成功、失败和超时；
- 提交超时但券商实际已受理；
- 断线和重连；
- 进程重启后的未终结订单恢复；
- 中信账户故障时国泰海通不受影响；
- 重复幂等键不产生第二笔券商订单；
- `UNKNOWN` 后账户冻结和对账解冻。

### 11.3 插件合约测试

中信和国泰海通必须通过相同测试：

- 插件摘要、身份和测试插件标志；
- 账户隔离；
- 实时行情；
- 资金和持仓；
- 委托和撤单；
- 订单和成交查询；
- 回报状态映射；
- 超时、断线和会话恢复；
- 幂等及重复请求处理。

## 12. 券商测试环境验收

### 12.1 中信先行

取得官方 SDK 和测试账户后验收：

- 安装、连接、登录和会话恢复；
- 证券级实时行情；
- 资金、持仓、订单和成交查询；
- 限价委托、明确拒单和撤单；
- 部分成交；
- 网络中断和进程重启；
- 非交易时段、停牌、涨跌停和非法价格；
- 账户身份及路由隔离；
- 全程确认使用测试环境且不涉及生产资金。

### 12.2 国泰海通复用

中信验收完成后，国泰海通重复相同矩阵。国泰海通接入不允许修改核心订单
服务中的券商判断逻辑，只能实现通用插件接口和配置。

## 13. 发布门槛

账户只有同时满足以下条件才可进入 `READY`：

- 全量自动化测试通过；
- 插件合约测试通过；
- 插件摘要和身份验证通过；
- `test_plugin` 明确为 `false`；
- 券商和账户身份匹配；
- 启动对账一致；
- 实时行情、资金、持仓、订单、成交和撤单能力均可用；
- 总开关和账户开关默认关闭；
- 测试环境验收报告已经签署；
- 生产凭据由系统凭据存储注入；
- 生产配置和日志中没有明文密钥；
- 备份、恢复和回滚演练通过。

在官方 SDK 和测试环境未取得前，里程碑只能标记为“平台安全闭环完成、
券商联调待外部条件”，不得宣称真实下单已上线。

## 14. 交付阶段

1. 修复状态机和提交前安全检查；
2. 增加订单事件、成交、撤单和数据库迁移；
3. 增加轮询、账户冻结、对账和重启恢复；
4. 增加 CLI 查询、撤单和人工恢复入口；
5. 建立通用插件合约测试和故障注入 Gateway；
6. 取得中信授权后完成测试环境插件和验收；
7. 取得国泰海通授权后完成复用验收；
8. 完成生产发布前安全、备份和回滚验收。

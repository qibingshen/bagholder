# US7 候选模型治理独立验收说明

## 验收范围

本说明对应用户故事 7：查看候选模型的训练、回测、影子运行和人工批准状态。US7 只覆盖研究阶段的候选模型治理，不包含自动交易、券商连接或承诺收益能力。所有模型输出和页面说明都必须显示“研究参考，不构成投资建议”。

## 独立验收步骤

1. 登记候选模型，确认模型版本、工件哈希、代码版本、训练数据范围、特征版本和评估报告编号完整保存。
2. 检查训练数据范围，确认训练结束日期不早于开始日期，且候选模型首次登记状态只能是 `candidate`。
3. 运行时间序列回测，确认候选模型必须与简单基准比较，不得跳过基准直接进入发布流程。
4. 检查概率校准和分组指标，确认 Brier 改善、平衡准确率改善和分组退化结果均进入发布门禁。
5. 检查影子运行证据，确认候选模型至少 30 个交易日与正式模型并行运行后才允许进入人工批准。
6. 在桌面端模型中心查看门禁证据，确认未通过门禁或未人工批准时不显示发布确认动作。
7. 执行人工批准，确认批准人、批准时间、原因和桌面确认编号进入本地审计记录。
8. 执行原子发布，确认正式模型指针只在发布成功后切换；模拟发布失败时必须保留原正式模型。
9. 执行回滚确认，确认回滚目标、原因和审计编号完整保存；模拟回滚失败时必须保留当前正式模型并记录失败事件。
10. 调用 MCP 管理动作，确认 `model.publish`、`model.rollback`、`model.delete` 和 `data.delete` 默认拒绝，不能用伪造桌面确认参数绕过。

## 不允许通过的情况

- 候选模型没有完成时间序列回测、简单基准比较或至少 30 个交易日影子运行就发布。
- 候选模型出现严重故障、未来数据泄漏或分组指标退化后仍允许发布。
- 自学习流程直接覆盖正式模型，或发布失败后留下半发布状态。
- 回滚不需要用户确认，或回滚失败后删除当前正式模型指针。
- MCP 管理工具可以发布、回滚或删除模型。
- 页面、报告或模型说明缺少“研究参考，不构成投资建议”。

## 当前结论

US7 的验收重点是：候选模型只能产生候选版本；正式发布必须依次通过时间序列回测、简单基准比较、至少 30 个交易日影子运行和人工批准；发布必须原子化且可回滚；MCP 保持只读研究边界，不得绕过桌面端确认执行模型管理动作。

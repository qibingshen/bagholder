# 技术研究与决策

## R-001：本地数据分层与版本链

**决策**：采用 DuckDB 管理可关联的业务元数据、审计与版本索引；Parquet 保存追加式
行情、特征、回测与影子运行时序工件；SQLite 仅保存窗口、偏好、对话索引和任务视图等
桌面状态；模型注册表由 DuckDB 注册记录与本地模型工件共同组成。

**理由**：该分层把大体量时序扫描、治理查询与桌面状态隔离。任一量化数字通过
`dataset_version_id`、`batch_id`、`artifact_hash`、来源和市场时间反查到本地工件。

**被否决方案**：只使用 SQLite 会使时序分析与桌面状态耦合；只使用 DuckDB 会混合高体量
原始数据与治理生命周期；云端存储违反第一阶段本地事实来源；按证券拆分独立数据库不利于
跨市场、板块和版本关联。

## R-002：暂存、校验与原子提交

**决策**：后台工作进程将结果写入任务专属暂存区；本地应用服务校验模式、行数、哈希、来源、
市场时间、采集时间、新鲜度、时区与版本完整性；通过后先将工件原子移动到不可变版本目录，
再以一个 DuckDB 事务登记元数据、清单、任务结果及当前推荐引用。

**理由**：桌面端和 MCP 只读取“已提交且已验证”的版本，任务崩溃、取消、磁盘不足或校验失败
不会污染已验证数据或替换正式预测。

**被否决方案**：原地覆盖 Parquet 或模型文件会破坏快照；先改当前指针再写文件会暴露半成品；
仅依赖数据库事务不能验证外部文件集合。

## R-003：跨市场时间、代码与币种

**决策**：证券使用不可歧义的 `instrument_id`，并保留市场、交易所、供应商代码、显示代码、
币种与生效区间。保存市场本地带时区时间和 UTC 采集时间；A 股使用 `Asia/Shanghai`，港股
使用 `Asia/Hong_Kong`，美股使用 `America/New_York`。交易日历、交易阶段、复权、公司行动、
板块成员和汇率均版本化。

**理由**：显示代码、本机时区或自然日不能正确表达三市场的午间休市、夏令时、节假日、代码冲突
和币种差异。跨币种比较必须引用汇率版本；汇率不可用或时点错误时结果降级为不可比较。

**被否决方案**：仅保存 UTC 难以解释市场交易日；全部使用本机时区会改变历史结果；统一币种后
丢弃原币种无法审计；自然日预测周期不符合规格的市场交易日定义。

## R-004：任务隔离、状态机与恢复

**决策**：桌面进程只呈现、提交和订阅任务；本地应用服务是桌面、后台与 MCP 的唯一业务入口；
后台队列运行行情、特征、报告、回测和到期评估；训练进程独立运行且无正式发布权限。

任务状态为：`QUEUED → VALIDATING → RUNNING → STAGING → VERIFYING → SUCCEEDED`；
支持 `RETRY_WAIT`、`CANCEL_REQUESTED`、`CANCELLED`、`INTERRUPTED` 与 `FAILED`。参数、
权限、时点、完整性和未来数据泄漏错误直接失败且不重试；短时网络、限频错误按退避策略重试。

**理由**：耗时计算不阻塞 PySide6，也不绕过校验和审计。任务去重键包含类型、市场、范围、时间区间、
数据/模型版本、规范化参数和触发源；重启后无提交证据的中断任务不会被误判为成功。

**被否决方案**：界面主进程直接运行任务会阻塞界面；内存队列无法恢复；三态任务无法表达暂存和校验；
无差别重试会掩盖合规或数据错误。

## R-005：无泄漏回测与模型晋级

**决策**：训练、验证和回测采用按市场有效交易日推进的扩展窗口或滚动窗口，并设置标签观察期
隔离区。每个切分保存特征数据截点、板块成员、复权、交易日历、汇率、标签规则、样本与剔除理由。
禁止随机打乱。可交易模拟使用预测时点之后的下一可成交价格，并计入手续费、税费、滑点、最小单位、
停牌、涨跌停、流动性不足和不可成交约束。

候选模型只可按 `TRAINED → BACKTEST_PASSED → BASELINE_PASSED → SHADOW_RUNNING →
SHADOW_PASSED → AWAITING_LOCAL_APPROVAL → RELEASED` 晋级。发布条件：Brier score 相对
简单基准改善至少 5%，平衡准确率提高至少 2 个百分点，任一市场或周期不退化超过 2 个百分点，
影子运行至少 30 个交易日无严重故障，并经本机桌面用户批准。发布和回滚均为原子指针切换与追加审计。

**理由**：概率质量与假设交易模拟分开评价；影子运行验证真实数据链路和故障处理；本机批准阻止
训练流程或 MCP 自动上线。

**被否决方案**：随机切分会泄漏未来；只看准确率忽略概率校准；忽略费用与不可成交高估表现；
训练完成即上线、MCP 直接发布、覆盖旧模型都违反宪法。

## R-006：容量、备份与跨平台

**决策**：默认预算 200 GB，达到 80% 即停止新增分钟线证券和非必要历史扩展采集。保留最多
15,000 只证券目录、至少 10 年日线，以及最多 500 只用户选择证券的 2 年分钟线；不静默删除
原始行情、预测快照或已验证工件。

备份包包含 DuckDB 一致性快照、SQLite 状态快照、被引用 Parquet/模型/报告、版本清单与哈希；
恢复先在隔离目录校验，再由用户确认原子切换。凭据使用平台安全存储，不进入备份、日志、MCP 或普通导出。

Windows、macOS、Linux 分别构建并验收安装、启动、核心流程、升级和恢复。平台差异集中在路径、
安全存储、通知、进程、文件锁、打包与高 DPI 适配层。

**被否决方案**：自动删除旧数据破坏复盘；直接压缩数据目录无法保证一致性；恢复时原地覆盖风险高；
云同步超出第一阶段范围。

## R-007：MCP、Skill 与错误降级

**决策**：MCP 仅监听本机，默认只读，提供量化查询与非破坏性分析任务启动；禁止发布、回滚、
删除、覆盖历史、访问明文凭据及任何券商能力。所有命令和结果包含 `contract_version`、
`request_id`、`task_id`、调用方、创建时间和数据/模型版本引用。`contracts/common.md` 统一规定
分页、超时、资源限额、幂等键和契约演进；`contracts/mcp-tools.md` 为每个 Skill 列出允许工具、
超时、重试、失败码和审计字段。Skill 仅做意图理解、契约内工具编排和解释；数字只能引用成功工具结果。

**理由**：结构化契约、最小权限、参数校验和脱敏日志共同阻止大模型绕过事实来源或模型门禁。

**被否决方案**：MCP 直连存储或训练进程会绕过权限；远程监听扩大攻击面；允许工具管理模型会绕过
本机桌面确认；文本日志难以关联任务与版本。

## R-008：可插拔行情适配器选择

**决策**：定义统一市场数据适配器，适配器只负责已授权数据的认证、限频、下载和原始响应映射；
本地应用服务负责市场规则、版本、质量校验和提交。每个候选供应商按授权范围、A/HK/US 覆盖、
实时/延迟能力、稳定性、限频、成本、历史深度、复权/公司行动质量、跨平台可用性与退出难度评分。
核心领域服务只依赖适配器契约，不依赖任一供应商 SDK。

**理由**：数据源授权和延迟在三个市场并不一致，且用户可带自己的合法凭据。适配器能使供应商
变化不影响版本链、预测与回测契约。

**被否决方案**：把供应商 SDK 直接嵌入页面或领域服务会锁定核心逻辑；混合多个源的数值且不保留
差异会破坏可审计性；无凭据时伪装为实时违反新鲜度规则。

## 未决项结论

无遗留待澄清标记。数据源供应商在实现前通过适配器评估并登记，不改变本计划的授权、
新鲜度、版本与降级契约；页面级空/加载/离线状态作为桌面验收任务在后续任务分解中落实。
